# Bug Report: Testcontainers fails during `make test-backend`

**Type**: Dependency issue
**Severity**: High
**Feature**: 009-codebase-polish
**Reported**: 2026-07-13

## Description
When running `make test-backend`, the backend tests fail to start because Testcontainers cannot locate a valid Docker environment. This happens because the `test-backend` Make target runs `./mvnw test` inside the `backend` Docker container, but the `docker-compose.yml` file does not mount the host's Docker socket (`/var/run/docker.sock`) into the `backend` container, which prevents Testcontainers from spinning up the required PostgreSQL test database.

## Root Cause Analysis
Testcontainers relies on the Docker daemon to dynamically spawn disposable database containers during the JUnit test lifecycle. When the tests run natively on the host (e.g. `mvn test`), it works because it has access to the host daemon. However, when run inside the `laundry-backend` container via `make test-backend` (`docker compose run`), the container lacks access to the host daemon.

## Recommended Fix
1. Update `docker-compose.yml` to mount `/var/run/docker.sock:/var/run/docker.sock` in the backend service.
2. Ensure permissions allow the container to access it, or run `make test-backend` directly on the host if Docker-in-Docker is restricted.
