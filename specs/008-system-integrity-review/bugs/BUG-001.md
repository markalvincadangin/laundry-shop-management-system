# Bug Report: Missing Machine Assignment Backend Implementation & Load Constraints

**Type**: Implementation drift / Spec gap
**Severity**: High
**Feature**: feature/system-integrity-review
**Reported**: 2026-07-10
**Status**: Patched
**Patched**: 2026-07-10

## Description
During a review of the machine assignment business rules, two critical gaps were identified:
1. **Load Constraint Rule (Spec Gap)**: The spec (`FR-005`) dictates that an order can span multiple machines to support massive loads. However, there is no explicit business rule enforcing that the number of assigned machines must equal the `totalLoads` calculated for the order. The frontend only enforces a generic rule of "at least 1 machine" and "at most 10 machines" in `MachineAssignmentModal.tsx`.
2. **Missing Backend Implementation (Implementation Drift)**: Although the frontend `useOrders.ts` sends `machineIds` when advancing an order to `WASHING` or `DRYING`, the backend `UpdateOrderStatusRequest` DTO and `OrderStatusService` completely drop these IDs. Furthermore, the `Order` entity lacks the `@ManyToMany` join table required to persist machine assignments, meaning staff machine selections are currently lost.

## Artifact Traceability

### spec.md
- **Affected requirements**: `FR-005` (System MUST allow Staff to link an Order to one or more Machine entities... utilizing a join table)
- **Gap identified**: The spec fails to clarify whether the machine count *must* strictly match the `totalLoads` value. Additionally, the backend implementation for FR-005 was entirely skipped in previous task executions.

### plan.md
- **Affected sections**: Database Changes, Backend Implementation
- **Impact**: The backend plan must be updated to introduce the `order_machines` join table and incorporate `machineIds` in the status transition API.

### tasks.md
- **Missing tasks**: 
  - Add `@ManyToMany` mapping between `Order` and `Machine`.
  - Update `UpdateOrderStatusRequest` to accept `Set<Long> machineIds`.
  - Update `OrderStatusService.updateStatus` to persist the machine relationships.
  - Implement validation logic ensuring `machineIds` is required when moving to `WASHING` or `DRYING`.
  - Implement validation ensuring `machineIds.size() == order.totalLoads` (if this rule is officially adopted).

## Root Cause Analysis
The machine assignment capability was partially developed on the frontend but overlooked entirely during backend implementation. The data model changes for the join table (`order_machines`) were not executed, leading to a disconnected feature where the UI allows assignments that the API discards.
